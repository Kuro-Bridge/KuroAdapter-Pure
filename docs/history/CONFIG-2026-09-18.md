## 1 裁决总览

- **D1 首启生成**：config.json 缺失时自动生成安全默认配置并落盘，随后走正常解析路径继续启用（生成件即文档）。
- **D2 token 必配（安全默认）**：token 解析后为空（缺失或 `""`）→ **拒绝启动 WS 监听**，指路式报错后中止启用。取代"不鉴权裸奔"。对主仓"WARN 不阻断"为**有意偏差**（理由见 §3）。
- **D3 随机 token**：D1 生成件写入 32 位 hex 随机 token（`SecureRandom`，16 字节）。首启即用与安全默认由此同时成立：服务照常起，对端须从 config.json 抄 token 配置。日志只指路文件路径，**不回显 token 值**。
- **D4 serverId 配置化**：新增可选根字段 `server.id`（非空字符串），对齐主仓 ADR-034 字段形状；默认值 `kurobridge-pure`（与现常量一致，保留 Pure 运行时辨识度）；进程固定，改后需重启（与主仓一致）。
- **D5 reload 形态：命令触发，不做文件 watch**。`/kurobridge reload`（控制台与持权玩家）。理由：STATUS 第 5 条既登记命令形态；Pure 在进程内（主仓 IPC 帧面向 Node 子进程，不适用）；命令触发无后台线程、无半写文件竞态、确定性可测；主仓选 watch 是因其无法从游戏侧触发，Pure 无此限制。主仓 2s 轮询 watch 不移植（有意简化）。
- **D6 热/冷字段矩阵**：channels、admins 热更；token、ws.host、ws.port、server.id 冷（重启生效），reload 回执须明示哪些字段待重启。
- **D7 生成件形状**：`channels: []`、`token: <32hex>`、`admins: []`、`server.id: "kurobridge-pure"`、`ws: {host: "127.0.0.1", port: 25580}`——环回+固定端口是安全默认，也是对端静态 url 的开箱即用值；25580 与 koishi-dev 部署值及 SMOKE 登记一致（`SMOKE-2026-09-18.md:26`）。
- **D8 fail-fast 保持**：解析失败仍 SEVERE+中止启用（现状 `:129-133`）。对主仓"解析失败降级默认"为**有意偏差**，延续"错误配置不静默降级"纪律。

## 2 D1 细节：首启生成

- 时机：onEnable，`<dataFolder>/config.json` 不存在时（目录创建逻辑保留，`:117-119`）。
- 写入：`CREATE_NEW` 语义（等价主仓 `wx` 防覆盖；并发竞争时退回正常加载既有文件）。Jackson（:core 已有 2.18.0）pretty-print 落盘。
- 生成后**经由 ConfigLoader 正常解析该文件**继续启用（单一权威，不为生成件开第二解析路径）。
- 生成失败（IO）→ ConfigException 指路报错，中止启用。
- 运行期 reload 时文件缺失：**不重新生成**，保留旧配置并报错（生成仅发生在启用时；主仓 watch 的 missing→writeDefault 行为不移植）。

## 3 D2 细节：token 必配与权衡

- 执行点：onEnable，PureWsServer 构造**之前**；空 token→SEVERE 指路（文件路径+「在 token 字段设置非空令牌；对端须配置同一令牌；仅本机调试可用任意非空串如 dev」）后抛出中止启用。插件整体不启用（不注册监听、不开监听——不给半工作状态）。
- **与主仓偏差的理由**：主仓 ws 服务面是本机 Node 子进程回环场景、默认动态端口，裸奔暴露面小；Pure 是独立 WS 服务端，缺省=全接口+固定可连，token 空=任意对端可注入平台聊天、读 status/bindings（admins `[]` 虽拦住 command，但聊天注入与信息暴露成立）。0.1.0 预发布阶段、无存量部署，破坏性变更窗口就是现在；沙盒与 koishi-dev 配置均已有非空 token，真机不受影响。
- 不设显式"关闭鉴权"逃生门：本机调试用任意非空串即可，语义面更小。

## 4 D5/D6 细节：reload

- 命令：`/kurobridge reload`，权限节点 `kurobridge.reload`（paper-plugin.yml 声明，default op；控制台恒可）。注册方式实现期核实：paper-plugin.yml commands 块若 1.21.4 不支持则走 Paper Lifecycle/Brigadier API（二选一，结论写进 README）。
- 流程：读盘→ConfigLoader 解析；解析失败→**保留旧配置**+向发送者回显原因（对齐主仓 `relay.ts:295-297`）；成功→
  - `bindings.replace(channels)`（集合变化自动触发既有 `bindings_updated` 广播链路）；
  - admins：按新配置重建 `AdminTable` 并原子换入 relay（volatile 交换，具体落点实装定，语义=下一次 command 即用新表）；
  - token/ws/serverId：对比新旧，回执列出"待重启生效"字段。
- 可测性：生成/门禁逻辑放 :core 纯类（如 `ConfigBootstrap`），@TempDir 单测；Bukkit 壳保持薄（:paper 零单测现状不变，真机由块 B 补格）。

## 5 D6 对齐表（逐字段，主仓 config-schema ↔ Pure）

| 字段 | 主仓 | Pure 裁决 | 关系 |

## 6 实装与验收清单（块 A）

1. :core：`ConfigLoader` 增 `server.id` 解析（缺省/合法/空串抛/非串抛/server 非对象抛）；`PureConfig` 增 serverId；新 `ConfigBootstrap`（生成+门禁纯逻辑）+ `@TempDir` 单测（生成形状/round-trip 可解析/token 32hex 且两次不同/既有文件不动/生成失败指路）。
2. :paper：onEnable 接 bootstrap 与 token 门禁；serverId 改读配置；`/kurobridge reload` 命令 + AdminTable 重建 + 回执（热更/待重启分组）；绑定失败（端口占用）须 SEVERE 指路后中止启用（实证现状，缺则补）。
3. README 配置文档同步（逐字段表、首启行为、安全默认、reload 热冷矩阵——不写超前承诺）；STATUS 第 5 条对勾与测试计数刷新。
4. 门禁全绿（`gradlew build`，含 spotless）后 Conventional 中文提交，master 直提，不 push。

## 7 已知代价（明示）

- 存量"无 token 显式配置"从可用变为拒绝启动——0.1.0 预发布接受（§3）；文档须写明迁移一句话（设任意非空 token）。
- 生成件固定 25580：端口被占时首启失败，报错须指路改 config（而非回退动态端口——回退会静默破坏对端静态 url）。
